# Known issues

Current limits of Ledger Check. Details live in the module docstrings and `--help` named below.

- **Runs on the bundled synthetic invoices only.** No command reads an invoice of your own: `ledgercheck serve` and `ledgercheck judge` run the fixture and golden cases shipped in `ledgercheck/fixtures`, picked by case id. Offline intake returns a case's stored JSON invoice as the extraction; for a text-backed case it uses the paired JSON, and the `.txt` is never parsed (`ledgercheck.agents.intake`). From Python, `IntakeAgent(fixtures_root=...)` can load cases in the same fixture format from another directory. Parsing invoice text needs the live client (`IntakeAgent.extract_text`), which is not implemented (see the next item). There is no PDF input.
- **Live LLM mode is not implemented.** With `LEDGERCHECK_LLM=1` and `OPENROUTER_API_KEY` set, the live objects construct, but every live call raises `NotImplementedError` (`ledgercheck.agents.llm_client`, `ledgercheck.agents.routing`), so `ledgercheck judge --live` exits 2. Everything runs offline on the fixture path. The default model ids in `ledgercheck.agents.routing` are unchecked placeholders. Rate-limit (HTTP 429) and context-window handling are designed but not built; the runbook is in the `ledgercheck.agents.routing` module docstring.
- **Approval checks are incomplete.** Approval does not yet check total vs subtotal + tax, line amount vs quantity × unit price, dates (a due date before the invoice date approves), or duplicate resubmissions (see `ledgercheck.agents.approval`). The unknown-PO and PO-amount rules need a PO book; `run_pipeline` and `ledgercheck serve` pass none, so only golden cases that carry a `po_book` exercise them.
- **Padded vendor ids are not matched.** A vendor id with surrounding whitespace is looked up as-is (`PolicyCorpus.find_vendor` in `ledgercheck.agents.policy`), so it is reported as an unknown vendor. Padded PO numbers are stripped and match.
- **`ledgercheck serve` is local only.** It binds IPv4 loopback addresses (`127.0.0.0/8`) only and has no login (`ledgercheck serve --help`).
- **Langfuse tracing is untested against a real server.** Tracing is a no-op unless `LANGFUSE_PUBLIC_KEY` and `LANGFUSE_SECRET_KEY` are set. `LangfuseTracer` has only been tested against a fake SDK in `tests/test_observability.py`, never against a real Langfuse server (`ledgercheck.observability`).
- **Deployment files are an untested reference.** The `Dockerfile` packages the CLI; the test suite reads it but does not build the image. `terraform/` is an unapplied Azure Container Apps reference that nothing in this repo provisions, and it has not been run through `terraform validate` yet (`python3 scripts/deploy.py validate`).
